# Инструкция по развёртыванию (для ИТ)

Это техническая инструкция для команды, которая будет разворачивать приложение на своём сервере. Пользовательская документация — в [README.md](README.md) и [ADMIN_GUIDE.md](ADMIN_GUIDE.md).

## 1. Что нужно на сервере

- Linux-сервер (VPS или своё железо) с SSH-доступом
- Node.js 22 LTS
- PM2 (или аналог, чтобы процесс перезапускался автоматически) — либо Docker, если используете [Dockerfile](Dockerfile)
- nginx (или другой reverse-proxy) с SSL-сертификатом на домен/поддомен
- Домен или поддомен, либо путь на существующем домене (например `company.ru/novinki`)

## 2. Установка

```bash
git clone https://github.com/MBSokGT/novinki.git
cd novinki
npm install
cp .env.example .env
```

## 3. Настройка `.env`

Заполните файл `.env`, ориентируясь на комментарии в `.env.example`. Обязательно проверьте:

| Переменная | Что поставить |
|---|---|
| `NEXT_PUBLIC_BASE_PATH` | путь, если сайт не на корне домена (например `/novinki`), иначе оставить пустым |
| `SQLITE_DB_PATH` | **абсолютный** путь, например `/var/www/novinki/data/novinki.db` |
| `NEXT_PUBLIC_STORAGE_DRIVER` | `filesystem` — рекомендуется на новом сервере, чтобы фото/PDF не раздували базу (см. п.6) |
| `UPLOAD_DIR` | **абсолютный** путь, например `/var/www/novinki/uploads` (только если `NEXT_PUBLIC_STORAGE_DRIVER=filesystem`) |
| `ENCRYPTION_KEY` | сгенерировать новую случайную строку: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"` — **не копировать** из `.env.example` и не переносить со старого сервера |
| `APP_URL` | полный URL, например `https://company.ru/novinki/reset-password` |
| `SINGLE_ADMIN_MODE` | оставить `true`, если сайтом будут пользоваться только сотрудники с логином-админом |
| `NEXT_PUBLIC_DEMO_MODE` | оставить `false`/пустым — иначе включится демо-режим с тестовыми данными и захардкоженным паролем |
| `PORT` | порт, на котором слушает Node-процесс (например `3001`) |

**Не копируйте `.env` и папку `data/` со старого сервера** (153.80.247.162) — там чужая база и чужой админ-аккаунт. Новый сервер должен стартовать с чистой базой.

## 4. Сборка и запуск

```bash
npm run build
```
Это соберёт standalone-сборку в `.next/standalone` и скопирует туда `public/` и статику (см. `scripts/copy-standalone-assets.js` — без этого шага сайт отдаёт пустую страницу).

Запуск под PM2:
```bash
pm2 start .next/standalone/server.js --name novinki-app
pm2 save
pm2 startup   # выполнить команду, которую покажет pm2, чтобы PM2 поднимался после ребута сервера
```

Или через Docker: `docker compose up -d --build` (см. [docker-compose.yml](docker-compose.yml)).

## 5. nginx

Пример location-блока (подставьте свой домен/путь и порт из `PORT`):
```nginx
location /novinki {
    client_max_body_size 20m;
    proxy_pass http://127.0.0.1:3001;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_hide_header X-Powered-By;
}
```

**`client_max_body_size` обязателен.** Без него загрузка фото/PDF будет падать с ошибкой 413 — nginx по умолчанию режет тело запроса на 1 МБ, а листовки часто крупнее. Если используете `NEXT_PUBLIC_STORAGE_DRIVER=filesystem`, лимит всё равно нужен (файл идёт через multipart-запрос), но требования к размеру не такие критичные, как в режиме `base64`.

Не открывайте порт из `PORT` наружу напрямую — только через nginx.

## 6. Постоянное хранилище: `data/` и `uploads/`

Это два каталога, которые **должны существовать вне `.next`** и **не удаляться при повторных деплоях**:
- `data/novinki.db` — вся база (товары, пользователи, заявки и т.д.)
- `uploads/` — фото и PDF-листовки товаров (только если `NEXT_PUBLIC_STORAGE_DRIVER=filesystem`)

Если деплоите через `git pull` + `npm run build`, эти папки не трогаются автоматически — просто убедитесь, что скрипт деплоя их не удаляет и не оказывается внутри `.next` (который пересоздаётся с нуля).

**Бэкапы**: настройте регулярное копирование `data/` и `uploads/` (например ежедневный cron на другой диск/облако) — это единственные невосстановимые данные во всём проекте.

## 7. Первый администратор

Единственный способ создать аккаунт — выполнить один раз на сервере:
```bash
npm run seed:admin -- ваш_email@company.ru "надёжный-пароль"
```
Публичной регистрации в приложении нет. После входа остальных сотрудников можно добавить через `/admin/users`, там же администратор может сбросить пароль любому сотруднику, если тот забыл (см. [ADMIN_GUIDE.md](ADMIN_GUIDE.md)).

## 8. Миграции

Миграции лежат в `migrations/` и применяются **лениво** — не при старте процесса, а при первом реальном обращении к базе (первый HTTP-запрос, трогающий SQLite). После деплоя с новой миграцией достаточно один раз открыть сайт или дёрнуть `/api/internal/data`, чтобы она применилась — специально накатывать миграции вручную не нужно.

## 9. Проверка после деплоя

1. Открыть сайт — каталог должен загрузиться (пустой, если это первый запуск).
2. Зайти в `/login` под первым админом, попасть в `/admin`.
3. Добавить тестовый товар с фото и PDF-листовкой, убедиться что они открываются.
4. Если использовали `NEXT_PUBLIC_STORAGE_DRIVER=filesystem` — проверить, что файл реально появился в `uploads/<bucket>/`, а не превратился в гигантскую строку в базе.
5. Удалить тестовый товар.
6. Настроить бэкапы `data/` и `uploads/`, если этого ещё не сделали.
